# 阶段五补充计划：九图、提交反馈与运营后台

**目标**　在阶段六开始前，完成最多九张图片的发帖和编辑，修正提交无反馈，并补齐社区工作台及用户管理。

**范围依据**　[开发路线图](2026-11-11-development-roadmap.md)、[设计第 10–12 节](../specs/2026-11-10-feiyiyunxiang-design.md)和旧项目九图发布、列表与详情页。改动留在 codex/stage-5。完整消息中心、账号注销流程与合作、PK 真机补测沿用原阶段安排。

### 1. 发帖、图片审核与性能

- [x] 以现有发帖页复现空字段禁用且无提示。标题、正文、照片任意一项有内容即可提交，三项全空点击提交时明确提示。列表正文留在详情页，无标题时使用「图片动态」或「文字动态」。
- [x] 云端新增 communityStageImage，每次最多接收一张图片。按账号、目标帖子、发帖请求和图片标识隔离暂存记录，持久化成功结果供重试。相册和日记均创建独立加密图片，继续移除位置元数据。
- [x] communitySubmit 只接收有序暂存 ID 和原版图片索引，最多九项。原有单图记录可读，旧客户端请求兼容。事务确认归属、精确版本及暂存状态并一次性保存待审版本。旧版继续公开。
- [x] 小程序发帖页按选择顺序展示九图缩略预览、增删和进度。登录、逐张上传、提交审核都显示状态，失败保留表单和同一请求的已上传项，等待超时可重试。
- [x] 列表使用旧版单图、双列和三列布局，详情支持点开大图。图片分别受当前版本鉴权，列表在靠近视口时按有限并发取图。后台可查看并对照两个精确版本的完整图片组。
- [x] 覆盖 0、1、9、10 张边界，跨账号猜暂存 ID、旧图与待审图隔离、逐图重试、重复提交、下架，以及图片顺序和旧单图兼容。

### 2. 运营工作台和用户管理

- [x] 以真实查询提供待审帖子、待审评论、待处理举报、路线和活动概要。管理端新增按公开旅伴 ID 查找、分页浏览账户、查看好友及社区活动概要。
- [x] 管理员可暂停或恢复本项目的微信会员账户，变更原因必填，撤销已有会话并写审计。社区禁言仍按时长管理。用户页联动作者帖子、评论审核和举报记录。历史公开内容通过现有下架与评论移除操作处理。
- [x] 云端校验管理员和审核员权限。用户管理响应只提供运营所需字段。验证普通会员及审核员无法停用账户，管理员不能通过恢复动作改变其他状态的账户。

### 3. 验收与交接

- [x] 在 app 执行 node --test 'tests/*.test.cjs'。本地编译微信小程序与后台 Web，检查标题图文、九图数量、上传进度和错误恢复，以及后台用户管理入口。
- [x] 在微信开发者工具检查校验与选图交互。记录真机、实际云端上传、后台安全域名及部署后才能验证的路径。更新阶段五验收，再进入第六阶段。


- [ ] 开发云更新后，验收真机九图上传和审核、后台计数及账户操作，再进入第六阶段。
