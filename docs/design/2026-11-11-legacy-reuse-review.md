# 旧版本地运行与复用评估

日期：2026-11-11。用户补充：旧数据库已清空，优先用本地演示数据查看旧项目，不写云端；希望较多内容直接复用。

## 当前运行结果

旧工程由 HBuilderX 5.15 运行 Web 调试，原始编译地址 `http://127.0.0.1:5319/`。另设独立预览地址 [旧版本地演示](http://127.0.0.1:5320/)，在独立端口提供本地账号和业务读接口，旧应用页面及样式照常由原编译器提供。

演示内容包括：19 个代码自带点位、10 个明确标注的流程占位点、3 条云接口模拟路线、3 条个人打卡记录、3 条社区帖子、1 名好友和示例评论。旧客户端自带的路线预设仍会显示，它们与模拟云路线不是同一份数据。

账号、定位、记录和帖子均为模拟，不能作为已删除历史数据的恢复。29 个点位中，新增的场景点坐标仅为界面流程占位，不代表真实展品位置或可发布路线。图片取自旧项目。

## 隔离方式

预览脚本位于 `.superpowers/legacy-preview/`，不是 app 或 admin 的产品代码。代理仅请求本机 5319 编译服务；替换预览页面中的 uniCloud SDK，并用本地固定数据实现查看所需的方法；未知方法不回退真实云对象。真实云函数调用、直接数据库访问和云存储上传均在该预览中拒绝。

模拟登录和定位只影响 5320 预览来源。顶部常驻“本地演示”说明。未上传 schema、种子数据、函数或素材，未使用实际用户账号登录或写入云数据。不能把这种模拟鉴权带到正式产品。

检查过预览 HTML 的引导脚本、SDK 替换响应和实际页面；展示代理返回正常，SDK 响应是本地 shim。验证的是预览机制和页面显示，不是云端业务正确性。预览暂不模拟所有写操作、AI、完整剧情资源发布和管理后台。

## 新发现

当前旧客户端 `app/utils/route.uts` 已有 ID 103、“海丝瓷绣”主题路线和封面 `static/route-planning/routes/macau_silk_route.png`，引用点位 4001—4007。旧库清空后真实点位资料不在本次找到的种子数据中；本地预览补的是明确标记的场景占位。

旧预设把长沙至澳门串成单条长距离路线，并显示约 830.7 km、178 小时及大量步数。这些旧计算不能直接继承。新版应改成澳门、湖南两条本地路线，由两名好友协作，而非要求一个人步行跨城。

运行日志发现原始旧工程实际使用的默认空间为支付宝云 `feiyiyunxiang / env-00jy72i6ol3c`，本地云目录也已经是 uniCloud-alipay；manifest 等仍有旧阿里云记录。原始接口返回“函数不存在或者没有生效的版本”，说明当前关联空间不仅缺少记录，还缺少可用的旧业务云函数。未尝试部署恢复。

## 对新设计的调整原则

前一版四入口新草图已被用户最新确认的“旧版地图首页 + 左右跳转按钮 + 无底部 Tab”取代。当前方案见 [地图首页复用草图](2026-11-11-map-home-design.html)。用户端优先采用“旧版可用结构和组件 + 新版内容及流程”。

地图首页已确认保留：选定路线后地图只呈现该路线，底部突出当前目标和继续探索；侧边入口精简为新版需要的内容。二级页面通过返回按钮回到地图，不增加全局底部导航。

直接继承视觉与组件的候选：澳喵素材、配色、圆角卡片、地图控件、路线节点、打卡详情、日记图文、帖子和评论布局。需要重构的是微信身份、云端权限与数据模型、两地合作、PK、72 小时任务、社区发布审核等业务。

旧代码存在已知权限与接口问题，因此“复用页面”不等于整套旧后端照搬。原生地图封装仍须适配微信小程序并真机验证，Web 能显示不代表微信端已验收。

## 重启预览

先在 HBuilderX 中将旧 `app-latest/app` 运行到 Web，保持 5319 编译服务存活。然后在新项目根目录运行：

```powershell
node .superpowers/legacy-preview/server.cjs
```

打开 `http://127.0.0.1:5320/`。关闭 HBuilderX 或编译服务后，演示页面会无法继续加载；没有恢复云端的依赖或数据写入步骤。模拟数据由脚本生成至同目录 demo-data.json，浏览器本地缓存仅用于预览。
