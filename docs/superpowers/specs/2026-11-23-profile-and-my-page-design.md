# 用户资料与「我的」页面设计建议

状态：下一轮待实施。需求来源是项目方 2026-11-23 的反馈：支持自定义昵称、头像，在帖子、排行榜、加好友等位置一致展示，并优化「我的」。本轮仅完成消息入口修正和本设计，不提前实现资料功能。

## 方案与默认选择

1. 只改「我的」表单：改动少，但评论、好友和排行榜仍可能显示旧快照，不满足需求。
2. **推荐：统一资料服务＋所有展示端接入＋现有后台人工审核**。新资料审核前保留旧资料，审核后统一读取当前公开资料，沿用项目现有治理方式。会增加资料待审工作，但不依赖尚未接入的微信内容审核回调。
3. 直接编辑微信账号／每处单独取微信资料：项目只能维护本应用资料，且难以保证跨端一致；不采用。

昵称、头像和「我的」信息布局是项目方明确要求。下面的简介、城市标签、文化兴趣与人工审核是建议默认值；新会话执行本计划时可按项目方补充意见调整，不能写成已经获得独立产品验收。

## 用户可设置的资料

| 字段 | 建议规则 | 展示范围 |
| --- | --- | --- |
| 昵称 | 去首尾空白后 2–20 Unicode 码点；拒绝控制字符；允许重名，身份仍靠稳定邀请码 | 所有当前公开署名 |
| 头像 | 默认澳喵／主动选图；仅 JPG、PNG，去除元数据，服务端校验；压缩后最多 1 MiB | 已通过头像用于帖子、评论、好友、排行榜 |
| 一句话简介 | 可空，最多 80 码点 | 我的资料，不塞入每张帖子卡 |
| 城市标签 | 可空，最多 20 码点，由用户主动填写 | 可选资料展示；不作为定位或合作地区依据 |
| 文化兴趣 | 最多 3 项：湘绣、瓷器、传统建筑、非遗美食、博物馆、摄影 | 资料标签，不改变匹配算法 |

不收集真实姓名、生日、手机号或精确住址。邀请码继续保持原值并可复制；不把改昵称变成改身份。路线所在地区、合作席位、定位范围、步数真实性不会由资料字段改变。本轮不扩展私信、账号注销、公开个人主页或好友推荐。

## 「我的」页面

1. 顶部资料卡：头像、当前昵称、稳定邀请码及复制、编辑资料。游客显示登录入口，不能先伪造一套可保存资料。
2. 快捷入口：消息（未读红点）、我的帖子（保留驳回提醒）、探索档案；每项标题与副说明清楚，保持已有页面和返回路径。
3. 澳喵：未领取时保留现有领取引导；已领取后改为紧凑卡片，显示角色与「带澳喵去探索」，保留形象，不让大插画占满首屏。
4. 探索与旅伴：档案、文化作品／旅伴记录仍从原入口访问；增加步数中心与旅伴的明确入口，不复制这些页面的业务状态机。
5. 页面底部保留隐私指引、退出登录；自动同步设置沿用现有步数中心，不增加另一份开关。

编辑页展示当前公开资料、待审修改、审核状态／驳回原因。选择／取消头像不改变公开资料；提交失败保留本账号草稿和同一请求标识。提交成功但刷新失败只重试读取。审核中继续展示原昵称与头像；无旧资料时使用现有默认资料。新提交替代旧待审版本，旧审核员不能误审新版本。

## 数据与权限

- fy-profiles 继续以现有 uid／code 标识本人，增加可选 revision、pendingRevisionId、bio、displayCity、interests、avatarMedia、avatarVersion。旧记录缺省 revision=0、空简介／标签、默认头像。兼容历史非标准主键，按实际记录更新，不建立第二份资料。
- 新增私密 fy-profile-revisions：不可变的提交快照、作者、baseRevision、状态、原因、时间与 order；新增私密 fy-profile-uploads 存头像暂存、归属和有效期。客户端直接读写仍全部关闭。
- getMyProfile／profileSubmit／profileStageAvatar／profileRevision 只允许当前有效小程序本人，忽略传入 uid；管理员令牌不能当本人令牌使用。
- profileReviewList／profileReviewDetail／profileReviewAvatar／profileReview 仅允许现有审核员／管理员；沿用现有审计集合，资料发布、审计和本人审核结果消息同事务。审核不得停用账号或改其登录身份。
- PublicProfileSummary 只含 code、nickname、avatarVersion；可选资料详情另行投影，不返回 uid、openid、头像存储 ID、待审资料或密钥。
- profileAvatar 用 code＋avatarVersion 读取**当前已通过**头像，仅在账号正常、版本仍匹配时返回去元数据的图片；权限／版本校验在下载后再做一次。头像继续加密存储并使用现有私密密钥管理，不开放存储桶，也不接受任意外部 URL。

## 展示一致性与历史

发布后按当前资料关联帖子卡／详情、公开评论、社区路线榜、每日步数榜、邀请码查找、好友申请／好友列表、合作与 PK 的已有私有旅伴标签，以及后台用户与审核卡。旧内容无需批量重写，缺失／停用资料有统一回退。用户身份不能用昵称关联。

旧帖子／评论里的 author 和好友消息里的 actorNickname 作为历史快照保留；审计中保留操作当时资料，不能随改名重写历史。当前界面展示当前公开昵称；对方不可用时可回退到历史昵称。双城终章等对外展示的「澳门旅伴／湖南旅伴」席位标签继续保持，不公开参与者身份。

头像组件按 code＋avatarVersion 缓存最多 40 个本地预览，最多 3 个并发读取，失败单独重试，属性变化后丢弃旧响应；切账号清除本人待审头像和编辑草稿。旧客户端仍能读取原 nickname／avatar 字段；不得把加密文件 ID 填进原 avatar URL 字段。

## 审核消息

新增 profile.approved／profile.rejected 两类本人消息，事件键包含收件人、资料修订和决定；重试不能覆盖已读。notificationDetail 可选 profileTarget={revisionId}，仅返回收件人自己的修订。详情相关按钮打开资料编辑页的对应审核结果；历史修订只读，明确点击「以此修改」才建立新草稿。原好友／帖子消息 DTO 和按钮路径继续兼容。

## 验收与参考

必须覆盖跨账号、并发提交／审核、响应丢失、旧修订、取消选图、上传失败、待审保留旧头像、驳回原因、账号停用恢复、老资料缺字段、旧头像读取失败、显示长度及 390/375/430 宽布局。构建、本机模拟、浏览器模拟、开发云与真机分开记证据。

选图优先沿用社区已有的 uni.chooseImage 与压缩／清理能力。微信 chooseAvatar 可作为便利入口，执行时须以 HBuilderX 5.15 和实际微信基础库实测支持情况，不把该入口作为保存资料的唯一途径。参考 [DCloud 选图文档](https://doc.dcloud.net.cn/uni-app-x/api/choose-image.html)、[DCloud 按钮文档](https://doc.dcloud.net.cn/uni-app-x/component/button.html)；已核对官方文档列出的选图和 chooseAvatar 能力，具体设备兼容仍需执行期验证。
