# 阶段二实施计划

依据已确认完整设计、地图修订、路线图及阶段一验收；保留布局、澳喵、功能分包。当前会话直接实施，各单元本地提交，不推送或部署。

1. 补阶段一技术复核：状态 reducer、两地切换、清除、跨页返回、非法参数；检查小屏展开时控件遮挡。重新编译核对源 AppID 与产物，不把本地检查记为真机通过。
2. 配置审计与部署门禁：核对 app/admin 空间，uni-id 配置存在性，支付宝私有目录能力。源配置为准；密钥只在云端。资料不足明确列出，不使用旧工程密钥。
3. 服务端领域与持久化：发布不可变路线版本，run 固定快照；独立 checkins、media、diary。所有集合默认拒绝客户端直接读写；事务与确定性主键保障重试/并发；记录服务端时间。
4. 身份：微信 code 仅服务端交换，uni-id-common 签发并校验；数据库二次验证账号和令牌，管理员角色实时读取。管理员密码使用 scrypt，首次管理员仅离线受控初始化，无公开提权接口；登录限流。
5. 媒体与打卡：受控服务端上传，校验格式/大小，媒体绑定 uid/run/节点/requestId；私有目录外叠加 AES-GCM 加密，客户端不持有解密密钥或原文件 ID。服务端验证定位、照片、版本；原子保存打卡与日记，进度从独立记录计算。失败保留草稿和相同请求编号。
6. 页面接入：轻量共享 API 和会话恢复；路线/点位读云端，开始探索、定位选图提交、档案日记；游客可浏览。后台登录、博物馆及路线节点草稿、编辑冲突检测、发布。社区/剧情/旅伴仍标明待开发。
7. 验证交付：身份失效/撤销、越权、媒体替换、定位边界、相同及不同请求并发、发布版本、上传与事务失败恢复测试；微信/后台编译。输出部署文件、配置项、目标空间及云端/真机待测清单。

重点风险：支付宝事务真实并发语义、私有目录实际权限、两端默认空间一致性必须在授权后的隔离开发空间验证。本地内存适配测试不能代替云端联调。未经内容核实不发布真实馆方坐标；后台只允许明确标识的开发测试内容，生产发布需内容确认。
