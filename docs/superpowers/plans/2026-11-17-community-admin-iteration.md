# 非遗云享社区与管理端迭代计划

## 目标与范围

让审核员能从工作台找到待处理内容、对照帖子版本并留下处理记录，让管理员能查找用户、查看相关内容并安全执行禁言、停用和恢复。同步打通作者查看审核结果及从「我的」进入社区记录的路径。先完成现有社区和后台的闭环，再进入单馆试点。

- 延续 uni-app x 微信小程序、Web 管理端和支付宝 uniCloud。后台继续使用独立后台会话，治理操作复用现有帖子版本、事务、媒体授权和审核记录。
- 「我的」保留当前澳喵图及领取恢复。路线、地图、馆内任务、剧情和 AR 由对应同事负责。单馆试点、站内私信、步数榜、正式换装以及全站消息中心分别按原计划推进。
- 每项改动从最新 `origin/main` 的独立 `codex/` 分支开始。优先使用独立 worktree 保留原工作区，验证后以 `main` 为 PR 基线。云函数、Schema、索引及小程序上线另行授权。

## A1 工作台和审核队列

涉及 `admin/pages/index/index.uvue`、`CommunityOverview.uvue`、`CommunityGovernance.uvue`、`communityOverview` 和 `communityReviewList`。

- [ ] 指标卡显示当前待审帖子、待审评论、待处理举报和公开帖子数量。待审帖子计数与列表统一使用仍可处理的最新待审版本；先核对事务与历史数据，再决定是否需要补查询或索引。
- [ ] 审核页突出当前队列、筛选和刷新状态。列表给出对象类型、状态、提交时间、文字摘要和可用的图片数量。兼容旧单图及时间缺失的记录。空队列、读取失败、加载更多失败分别给出相应操作。
- [ ] 工作台跳队列、用户管理跳按用户筛选的队列，以及返回后的刷新都可复现。切组或换筛选清空旧游标，翻页保持稳定顺序和当前筛选。任何一次失败都保留可重试入口。
- [ ] 验收有数据、空队列和中途刷新失败。至少构造一条已被新版本取代的旧待审记录，验证它和指标使用同一口径。测试队列跨至少两页时无重复和漏项。

## A2 帖子、评论和举报处理

涉及 `CommunityGovernance.uvue`、`communityReviewDetail`、`communityReviewImage`、`communityReviewPost`、`communityReviewComment`、`communityResolveReport`。

- [ ] 详情明确标出当前公开版、当前选中审核版、用户举报指向的版本。保留两版标题与正文的对照。按序预览本版最多九张社区图片，图片按需加载，失败可单独重试；切换记录清除上一条的图片和原因。
- [ ] 按对象实际状态显示通过、驳回、下架、移除评论和结束举报。状态变更提示明确目标及版本，驳回、下架、移除和处理举报时按服务端要求填写原因。区分操作成功、成功后刷新失败、旧版本冲突和权限拒绝。
- [ ] 两人同时审同一版本时，只有一次状态转移和对应审计生效。改帖待审期间游客继续读取审核通过的版本，通过后切换到新版；下架后原分享和社区图片入口按现有授权规则失效。
- [ ] 核对举报指向的帖子版本和评论归属。测试九图、旧单图、审批竞争、内容下架后的分享回流，以及旧社区帖子兼容。

## A3 用户管理与操作回执

涉及 `CommunityUsers.uvue`、`communityUsers`、`communityUserDetail`、`communityAccountStatus` 和 `communityMute`。

- [ ] 保留公开旅伴 ID 精确查找，完善输入格式提示、空结果、清除筛选和重试。账户状态明确区分正常、运营停用及其他状态；禁言单独显示剩余时间或截止时间。保留账户列表游标和当前用户详情的联动。
- [ ] 用户详情集中展示公开 ID、昵称、注册时间和运营所需计数。提供带用户上下文的待审／公开帖子、评论、举报、禁言及审计入口。核对这些入口标注的计数口径与目标列表范围。
- [ ] 停用、恢复、禁言、解除禁言各有独立确认对象与原因。确认弹窗用发起时选定的用户和原因提交，防止选择切换后误操作。沿用停用与恢复撤销会话的规则。只允许恢复由运营停用的账户，沿用其余账户状态的服务端限制。
- [ ] 写入成功后刷新详情及列表，刷新失败有独立重试，保留已成功的结果。测试查询无账号、有账号但无公开资料、禁言时长边界、停用和恢复时旧会话失效，以及审核员直接调用用户管理接口被拒绝。

## A4 权限、审计和词库

涉及 `fy-api/index.js`、`admin-session.js`、`community-service.js`、`community-operations.js`、`CommunityGovernance.uvue` 和相应 Schema／索引。

- [ ] 理清现有平台管理员和审核员的权限矩阵。审核员处理帖子、评论、举报及社区禁言；账户停用、恢复、用户管理和词库修改由管理员执行。按钮与云端行为保持一致，每次操作从后台会话核验身份。现阶段沿用已经定义的两种角色，逐项记录实际权限。
- [ ] 修正带用户上下文的审计和禁言列表。目前这两组的查询会忽略该用户筛选。禁言按账号过滤；新增审计通过可验证的对象归属记录目标用户，以适合既有游标的方式查询，按需增加索引。旧审计继续在全局页可见；无法确认历史归属的记录留在全局页。
- [ ] 审计由操作成功的事务生成，展示时间、操作员、动作、对象、版本与原因。审核图片走已有版本授权，后台接口仅返回完成治理所需字段。原始私密打卡照片和日记保留本人读取规则。
- [ ] 词库与限流页面明确只读／编辑态，沿用现有版本冲突校验。验证同时编辑、提交失败后保留输入、非法词条、评论拒绝优先级和限流。测试用户筛选不能串记录，写入失败不留成功审计。

## A5 小程序作者端与「我的」

涉及 `community.uvue`、`community-post.uvue`、`community-compose.uvue`、`account.uvue` 和 `my-checkins.uvue`。

- [ ] 「我的」保留默认澳喵和探索档案，精简次级入口。若增加「我的帖子」快捷入口，复用社区已有作者视图和账号校验。现有社区、作品、旅伴隐私入口保持可达。
- [ ] 我的帖子清楚展示待审、驳回、已通过与下架，以及允许查看、编辑或撤回的操作。编辑时保留当前公开版的提示；作者本人可看所选版本及审核原因，分享继续按当前公开版授权。
- [ ] 复测相册与日记混合九图、新旧版本、失败图定位和重试。测试从私密日记选图后，社区图片副本按社区权限读取，原日记照片仍由本人访问，上传副本按已有规则清除位置元数据。
- [ ] 验收同账号重登后的澳喵领取与档案恢复、空档案、照片失败重试，确认换装区域仍按当前决定暂缓开放。
